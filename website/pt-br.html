Esquema Isolamento rootless como valores Scheme

01 / Visão geral

Contêineres definidos na própria linguagem do Guix.

O Esquema mantém a carga de trabalho, a política de isolamento e os limites de recursos em Scheme. Um contêiner é um valor de primeira classe, não um documento YAML enviado a um serviço privilegiado.

01 — DECLARATIVO

Scheme da definição à execução

Use make-container, argumentos nomeados e composição comum do Guile. Gere contêineres, compartilhe funções e mantenha a política junto à configuração do sistema.

02 — ROOTLESS

Nenhum root do host é necessário

A carga pode aparecer como UID 0 dentro de seu namespace de usuário, enquanto é mapeada para o usuário comum que iniciou o processo no host.

03 — SEM DAEMON

Nenhum plano de controle privilegiado sempre ativo

O processo chamador cria a sandbox, executa a carga, aguarda sua conclusão e retorna o código de saída.

04 — REPRODUZÍVEL

Projetado para GNU Guix

Use o manifesto e os caminhos do Guix store. Para reproduzir dependências, fixe também as revisões dos canais: o manifesto sozinho não as fixa.

05 — EXPLÍCITO

O isolamento fica visível no código

Namespaces, montagens, ambiente, hostname, seccomp, tratamento de capabilities, modo do rootfs e limites são representados diretamente.

06 — ENXUTO

Camada Guile fina, primitivas C endurecidas

O Guile fornece a interface declarativa, enquanto a configuração de baixo nível dos namespaces e dos controles de segurança é realizada por uma biblioteca C focada.

02 / Esquema 0.3.0

Políticas explícitas. Requisitos verificáveis.

O modo de compatibilidade tenta aplicar cgroups e Landlock. O modo estrito exige as proteções configuradas. Os contêineres compartilham o kernel Linux do host.

01

Namespaces e identidade

Sete namespaces por padrão. O uid 0 interno é mapeado para o usuário do host; capabilities são removidas e no_new_privs é ativado.

02

Política seccomp versão 1

Valida arquitetura, famílias de sockets, io_uring e ioctl. Chamadas perigosas têm negação fatal; ABIs não nativas são rejeitadas.

03

Landlock e descritores

Restringe os acessos tratados à nova raiz. Descritores acima de 2 são fechados, exceto os delegados explicitamente. Landlock não revoga descritores abertos.

04

Limites verificados

O modo estrito exige cgroups v2 delegados, pelo menos um limite de cgroup e RLIMIT_NOFILE versão 1. Falhas interrompem a inicialização.

05

Montagens e raiz

Destinos bind rejeitam travessia. O modo estrito exige as APIs de montagem necessárias; uma raiz estrita somente para leitura exige aplicação recursiva e verificação.

06

Supervisor PID 1

Encaminha sinais, recolhe descendentes e passa de TERM para KILL após o prazo. É habilitado automaticamente no modo estrito.

Scheme · strict / Fortress
(use-modules (esquema runtime) (esquema container))

(exit
 (run-container
  (make-container "worker" "/absolute/path/to/rootfs"
                  '("/bin/sh" "-c" "echo confined")
                  #:strict? #t
                  #:rootfs-ro? #t
                  #:limits (make-limits-v1 (* 256 1024 1024)
                                          128 50000 100000 1024))))
Exemplo: 256 MiB, 128 processos, 50% de uma CPU e 1024 arquivos abertos. O rootfs precisa conter /bin/sh e suas dependências. A configuração exige Landlock, delegação de cgroups e APIs de montagem adequadas. Leia os limites da política.

make check

Testes C, funcionais e de segurança, cppcheck e regressão de instalação com staging, prefixos personalizados e módulos compilados.

02

make sanitize

ASan e UBSan nos testes C. make static executa o analisador do GCC.

07 / Esquema 0.3.0

Onde o Esquema se encaixa.

Uma biblioteca para políticas de contêineres em Scheme, com integração Guix e instalação direta em Linux.

01

Linux

Namespaces, seccomp e Landlock são APIs Linux. BSD, macOS e Windows precisam de uma VM Linux; suporte nativo não está implementado.

02

Scheme + C

Componha configurações com Guile. A biblioteca C executa a configuração de baixo nível e expõe uma API pública.

03

Rootfs

Prepare o executável e suas dependências em um diretório. O runtime não baixa imagens OCI nem fornece uma CLI compatível com Docker.

08 / Orientações de produção

Mantenha a página estática e o caminho de publicação restrito.

Este arquivo não realiza requisições a terceiros, não contém JavaScript, define uma CSP com hash fixo para o estilo inline e não usa cookies, analytics, fontes web ou imagens remotas.

ROOTFS

Minimize e sele

Prefira um binário estático para o servidor e um rootfs somente leitura. Adicione apenas os arquivos, montagens e dispositivos necessários à carga de trabalho.

REDE

Vincule localmente

Escute em uma porta loopback não privilegiada e exponha-a por um proxy reverso HTTPS com limites de taxa e cabeçalhos de resposta rigorosos.

POLÍTICA

Preserve os padrões

Não desative seccomp nem a remoção de capabilities para executar uma carga incompatível. Ajuste a carga ou adicione a menor exceção devidamente revisada.

OPERAÇÕES

Atualize e monitore

Mantenha o kernel compartilhado do host atualizado, monitore encerramentos de processos e pressão de recursos e execute novamente a suíte de segurança após mudanças no runtime.

09 / Perguntas frequentes

Respostas operacionais.

As distinções mais importantes antes de implantar uma carga de trabalho.

O UID 0 dentro do contêiner é root no host?

Não. Com o namespace de usuário padrão, o UID 0 interno é mapeado para o UID comum que iniciou o processo externamente. O conjunto de capabilities também é esvaziado, e os controles securebits e no-new-privileges impedem que o UID 0 recupere a semântica normal de root.

Por que o servidor web fica inacessível com a lista padrão de namespaces?

O padrão inclui um namespace de rede privado; por isso, a carga enxerga apenas o loopback, não as interfaces do host. Uma implantação acessível pelo host omite deliberadamente net, ou deve adicionar um mecanismo de rede explícito.

O Esquema pode substituir uma VM para código hostil?

Não se deve presumir equivalência geral. O Esquema adiciona controles robustos de contêiner, mas compartilha o kernel Linux. Use uma VM ou microVM quando o modelo de ameaças exigir uma fronteira de kernel separada.

Por que montar /gnu/store na demonstração com BusyBox?

O binário BusyBox do Guix é vinculado dinamicamente e precisa de seu carregador e de suas bibliotecas. Montar o store como somente leitura disponibiliza essas dependências. Um servidor web vinculado estaticamente remove essa dependência e reduz a superfície visível.

Os cgroups v2 sempre aplicam o limite solicitado?

No modo de compatibilidade, não há garantia obrigatória. O modo estrito verifica os limites solicitados e interrompe a inicialização se a delegação ou a aplicação falhar.

Esta página contém JavaScript ou recursos externos?

Não. Trata-se de um único arquivo HTML com CSS incorporado, favicon em data URI e nenhuma requisição externa. Todas as animações usam CSS e são desativadas quando o usuário solicita movimento reduzido.
